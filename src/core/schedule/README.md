# ⑤ schedule — 타임슬롯 편성

업무 5단계 중 **⑤ 면접 일정 분배**. 이 프로젝트의 심장이다.

## 들어오는 것 / 나가는 것

```
Applicant[] + Cfg  ──▶  scheduleAuto()  ──▶  Result { placed, unplaced, dates, times, ... }
Result             ──▶  validate()      ──▶  Validation { r1, r2, r3, r4 }
Placed[]           ──▶  blocksOf()      ──▶  Block[]   (연속 입장 구간)
```

## ⚠️ `sched.js` 는 함부로 고치지 않는다

`sched.js` 는 **검토서에서 실측 검증을 마친 코드**다. 재편 때는 위치만 옮겼고 내용은 그대로였다.

- **타입 주석을 달지 않는다.** 다는 순간 그 파일을 고치는 것이 되고, 측정치(위반 건수·소요일·결정성)를
  다시 받아야 한다. 타입은 `index.ts` 에 따로 선언되어 있다.
- 확장자도 `.js` 그대로 둔다.
- UMD 꼴이라 브라우저에서는 `globalThis.Sched` 로 붙고, Node 에서는 그대로 `import` 된다 —
  그래서 테스트가 React 도 브라우저도 없이 돈다.

편성 규칙을 정말 바꿔야 한다면, 고치기 전에 `__tests__/sched.test.mjs` 가 통과하는 상태를
먼저 확인하고, 고친 뒤 다시 확인한다.

### 고친 이력

**2026-09-02 — ⑤ 병목 팀 선배치** (배치 순서 규칙 한 곳: `order` 정렬)

학력 그룹 안에서 **하루 세션 수를 넘는 팀을 먼저** 앉힌다. 그다음은 종전대로 수요 오름차순이다.

④(첫 타임을 수요 적은 팀에)를 위해 오름차순으로만 넣으면, 작은 팀들이 첫날을 채우는 사이
정작 하루에 다 못 들어가는 팀이 맨 뒤로 밀려 남은 자리만 받는다. 그 팀이 넘긴 인원이 다음 날로
가는데 ②(한 팀은 한 세션에 한 명) 탓에 남은 팀 수만큼만 열이 차서 격자가 반쪽으로 빈다.

라이트 데모 실측(60명 · 8세션 · 4조 · `data/` 실제 엑셀):

| | 전 | 후 |
|---|---|---|
| 하드 제약 ①② | 0 / 0 | 0 / 0 |
| 미래혁신팀 학사 1일차 배치 | 5 | **8** (하루 상한) |
| 학사 블록 종료 전역 세션 | 15 | **13** |
| 석사 시작 일차 | 3일차 | **2일차** |
| 2일차 좌석 | 15 / 32 | **26 / 32** |
| 일수 | 3 | 3 (`minDays` = ⌈17÷8⌉ 이라 안 줄어든다) |
| ③ 연속 끊김 / ④ 첫 타임 | 2 / 14 | 1 / 14 |

③④ 는 `src/lite/arrange.ts` 의 정리 패스를 거친 뒤 값이다. 엔진 단독 값(정리 없음)은
전 6 / 13.

**검토서의 실측치는 이 변경 이전 기준이다.** `scoreSlot()` 가중치·`autoRooms()`·`validate()`
는 손대지 않았다. 회귀는 `sched.test.mjs` 의 「하루에 다 못 들어가는 팀을 먼저 앉힌다」가 지킨다 —
팀 수가 조 수보다 많아야 재현되므로(팀 ≤ 조 이면 각 팀이 제 조를 차지해 세션이 안 찬다)
합성 데이터는 4팀 3조로 잡았다.

## 제약 네 가지

| | 내용 | 성격 |
|---|---|---|
| ① | 학력을 시간축에서 섞지 않는다 | 하드 — 항상 0건 |
| ② | 같은 팀·같은 면접관은 같은 시간대에 1건 | 하드 — 항상 0건 |
| ③ | 같은 팀은 연속으로 배치한다 | 소프트 — 적을수록 좋다 |
| ④ | 첫 타임을 피한다 | 소프트 (`hard` 로 올리면 공석을 허용) |

## 왜 일수가 더 안 줄어드나

② 때문에 **한 팀이 하루에 볼 수 있는 면접은 1일 세션 수가 상한**이다.

```
최소 소요일 = ⌈가장 많이 요청한 팀의 건수 ÷ 1일 세션 수⌉      ← minDays()
```

병목은 면접실이 아니라 면접위원단의 수다. 조를 늘려도 이 값은 내려가지 않는다.
