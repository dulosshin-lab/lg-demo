# ⑤ schedule — 타임슬롯 편성

업무 5단계 중 **⑤ 면접 일정 분배**. 이 프로젝트의 심장이다.

## 들어오는 것 / 나가는 것

```
Applicant[] + Cfg  ──▶  scheduleAuto()  ──▶  Result { placed, unplaced, dates, times, ... }
Result             ──▶  validate()      ──▶  Validation { r1, r2, r3, r4 }
Placed[]           ──▶  blocksOf()      ──▶  Block[]   (연속 입장 구간)
```

## ⚠️ `sched.js` 는 고치지 않는다

`sched.js` 는 **검토서에서 실측 검증을 마친 코드**다. 이번 재편에서 위치만 옮겼고
내용은 한 글자도 바뀌지 않았다 (`git log --follow` 로 확인할 수 있다).

- **타입 주석을 달지 않는다.** 다는 순간 그 파일을 고치는 것이 되고, 측정치(위반 건수·소요일·결정성)를
  다시 받아야 한다. 타입은 `index.ts` 에 따로 선언되어 있다.
- 확장자도 `.js` 그대로 둔다.
- UMD 꼴이라 브라우저에서는 `globalThis.Sched` 로 붙고, Node 에서는 그대로 `import` 된다 —
  그래서 테스트가 React 도 브라우저도 없이 돈다.

편성 규칙을 정말 바꿔야 한다면, 고치기 전에 `__tests__/sched.test.mjs` 27건이 통과하는 상태를
먼저 확인하고, 고친 뒤 다시 확인한다.

## 제약 네 가지

| | 내용 | 성격 |
|---|---|---|
| ① | 학력을 시간축에서 섞지 않는다 | 하드 — 항상 0건 |
| ② | 같은 팀·같은 면접관은 같은 시간대에 1건 | 하드 — 항상 0건 |
| ③ | 같은 팀은 연속으로 배치한다 | 소프트 — 적을수록 좋다 |
| ④ | 첫 타임을 피한다 | 소프트 (`hard` 로 올리면 공석을 허용) |

## 왜 일수가 더 안 줄어드나

② 때문에 **한 팀이 하루에 볼 수 있는 면접은 1일 세션 수가 상한**이다.

```
최소 소요일 = ⌈가장 많이 요청한 팀의 건수 ÷ 1일 세션 수⌉      ← minDays()
```

병목은 면접실이 아니라 면접위원단의 수다. 조를 늘려도 이 값은 내려가지 않는다.

## 고치려면 어디를 보나

| 바꾸고 싶은 것 | 볼 곳 |
|---|---|
| 기본 파라미터(세션 수·시간·휴식) | `sched.js` 의 `DEFAULT_CFG` |
| 배치 우선순위 | `sched.js` 의 `scoreSlot()` |
| 조 수 자동 산출 | `sched.js` 의 `autoRooms()` |
| 검증 규칙 | `sched.js` 의 `validate()` |
| 타입 선언 | `index.ts` |
