# 제약사항 테스트 엑셀

제약 하나에 케이스 하나. 손으로 세어 확인할 수 있을 만큼 작게 잡았다.
제약 자체의 설명과 기대값의 근거는 **[`docs/제약사항_정리.md`](../../docs/제약사항_정리.md)** 에 있다.

```bash
node scripts/make-constraint-cases.mjs        # 다시 만들기
npx vitest run tests/constraint-cases.test.ts # 기대값 확인 (13건)
```

## 올리는 법

케이스 폴더 하나가 한 세트다. 화면에서 **`취합파일.xlsx` 를 먼저**, 그다음 `희망지원자_*.xlsx` 를 전부 올린다.
**폴더를 섞지 않는다** — 지원자번호 대역은 겹치지 않게 만들었지만 팀 이름이 겹친다.

기준 설정은 화면 기본값(8세션 · 4조 · 오전 4세션 · 30분 · 휴식 5분 · 정리 켬)이다.

## 케이스

| 폴더 | 겨누는 제약 | 무엇을 만들어 뒀나 | 돌려 볼 스위치 |
|---|---|---|---|
| `C1_학력분리_하드` | **하드 ①** 학력 분리 | 12명(학사6·석사4·박사2)이 3팀에 뒤섞여 있다 | `separateEdu` 끔 → 위반 6건 · `eduBoundary: day` → 3일 |
| `C2_팀중복_하드` | **하드 ②** 팀 중복 | 한 팀이 10명 — 하루 8세션 상한을 넘긴다 | 없음(끌 수 없는 규칙) · 조 수를 늘려도 2일 |
| `C3_면접관중복_하드` | **하드 ②** 면접관 중복 | 두 팀이 면접관 '한지호' 한 명을 공유한다 | `checkInterviewer` 끔 → 한 사람이 두 방에 동시 입장 |
| `C4_합동면접_하드` | **하드** 자리·인원 유일성 | 요청 11건 중 한 명은 3팀 합동, 한 명은 2팀 합동 | 없음 |
| `C5_연속배치_소프트` | **소프트 ③** 연속 배치 | 6팀 > 4조 · 팀 크기 제각각 · 학사와 석사 혼합 | `contiguous` 껐다 켜기 → 팀 덩어리 13→10 |
| `C6_첫타임_소프트` | **소프트 ④** 첫 타임 | 팀 수요가 2·3·8·8 로 갈린다 | `avoidFirstSlot` off / soft / hard |
| `C7_병목팀선배치_소프트` | **소프트 ⑤** 병목 팀 선배치 | 한 팀이 12명(하루 상한 8 초과), 나머지 3팀은 3명씩 | 조 3개 / 4개 비교 |
| `C8_대상선별_제외규칙` | **편성 전 필터** | 마스터 미존재 · 면접관 미기재 · 학력코드 과정4 를 한 명씩 심었다 | 없음 — 제외 목록을 본다 |
| `C9_파일서식_경고` | **파서 규칙** | 헤더 5행 / 헤더명 '인원' / 값이 이름 아님 / 면접관 열 없음 | 없음 — 경고 배너를 본다 |

## 데이터 서식

실제 회신 파일(`data/희망지원자_*.xlsx`)을 따랐다.

- 4행이 헤더(`STD_HEADER_ROW`), 5행부터 데이터 — C9의 가온기술팀만 5행
- 표준 컬럼 21개 + 마지막 열이 면접관 — 취합파일에는 면접관 열이 없다
- 학력 코드: `과정1`=학사 · `과정2`=석사 · `과정3`=박사
- 이름·학교·전공은 전부 가상값이다
