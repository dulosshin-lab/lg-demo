## 2. 원인 (코드 추적 완료 — 다시 조사하지 말 것)

1. 학사 블록은 ⌈45 ÷ 4⌉ = 12세션으로 계획된다 → 1일차 8 + 2일차 앞 4. [`sched.js:180-186`](../src/core/schedule/sched.js#L180-L186)
2. 팀을 **수요 오름차순**으로 하나씩 배치하고(규칙 ④ 의도), 각 팀은 `home = oi % Rg` 조에 연속으로 몰아넣는다. [`sched.js:210-214`](../src/core/schedule/sched.js#L210-L214) · 비용 함수 `scoreSlot()` [`sched.js:146-155`](../src/core/schedule/sched.js#L146-L155)
3. 작은 팀들이 1일차를 먼저 채우므로, **진짜 병목인 미래혁신팀(학사 13건 > 하루 8세션)** 은 맨 마지막에 1일차 남는 자리 5개만 받고 8건이 2일차로 넘어간다.
4. 규칙 ②(같은 팀은 한 세션에 1건) 때문에 한 팀은 한 행에 한 칸만 쓸 수 있다. 2일차에 학사가 남은 팀이 3개뿐이니 한 행에 최대 3칸 → 4번째 열(1조)은 구조적으로 빈다.
5. 계획 구간(2일차 4세션) 밖으로 나가야 할 때마다 「한 세션 확장」 폴백이 돌아 [`sched.js:236-241`](../src/core/schedule/sched.js#L236-L241) 4조 혼자 14:45 까지 늘어나고, `eduBoundary:'session'` 이라 그 구간엔 석사를 못 넣어 석사가 3일차로 밀린다.

한 줄: **④(첫 타임을 작은 팀에)를 위해 오름차순으로 넣다가 병목 팀을 굶긴다.** 미래혁신팀이 1일차에 8건을 먼저 받았으면 2일차엔 5건만 남고, 나머지 팀들이 4열을 병렬로 채운 뒤 석사가 2일차 오후에 시작한다.

주의: 3일차 자체는 없앨 수 없다. `minDays` = ⌈17 ÷ 8⌉ = 3 (테스트 `sched.test.mjs:89` 가 이 값을 고정). 목표는 **일수 단축이 아니라 2일차 좌석 채움과 학사 블록 종료 시각 앞당김**이다.

## 4. 접근안 (권장 순)

**A. 병목 팀 선배치 (권장, 최소 수정)**
`order` 정렬을 두 단계로: 학력 그룹 안에서 `byTeam[t].length > S` 인 팀(하루 세션 수를 넘는 팀)을 **먼저**, 나머지는 기존 오름차순 그대로. 미래혁신팀만 앞으로 가고 나머지 순서는 변하지 않아 ④ 훼손이 최소다. `avoidFirstSlot:'soft'` 의 +22 가점이 살아 있으니 병목 팀도 빈 격자에서 첫 타임을 피해 1세션부터 깔고, 나중에 첫 타임 하나만 채운다(④ +1 예상).

**B. 수요 내림차순 전체 반전**
간단하지만 ④ 가 크게 늘고, 작은 팀들이 뒤에 몰려 ③(연속성) 도 흔들린다. A 가 실패할 때만.

**C. 엔진 무수정 — 라이트 설정 변경**
`src/lite/data.ts` 의 `sessions: 8` 을 엔진 기본 14 로 되돌리면 2일로 끝난다. 근본 원인은 그대로이고 「현행 운영은 8세션」 전제를 버리는 것이라 **사용자 결정 없이는 금지**. 옵션으로만 보고한다.

`scoreSlot()` 의 가중치(30/45/55/22)는 건드리지 않는다 — 검토서 실측 기준이고 이번 현상과 무관하다.

## 5. 측정 스크립트 (고치기 전·후 각 1회)

`src/lite/_probe.test.ts` 로 저장 → `npx vitest run src/lite/_probe.test.ts` → 결과 파일 확인 → **파일 삭제**(커밋 금지).

```ts
import { readFileSync, readdirSync, writeFileSync } from 'node:fs'
import { basename, resolve } from 'node:path'
import { it } from 'vitest'
import { buildSchedule, readRoster } from './data'
const ROOT = resolve(import.meta.dirname, '../../data')
const f = (p: string) => new File([readFileSync(p)], basename(p))
it('probe', async () => {
  const roster = await readRoster(f(resolve(ROOT, '취합파일.xlsx')))
  const files = readdirSync(ROOT).filter(n => n.startsWith('희망지원자_')).sort().map(n => f(resolve(ROOT, n)))
  const s = await buildSchedule(roster, files)
  const r = s.result, S = r.cfg.sessions, V = s.validation
  const out: string[] = []
  out.push(`placed=${r.placed.length} unplaced=${r.unplaced.length} days=${r.totalDays} r1..r4=${[V.r1, V.r2, V.r3, V.r4].map(v => v.length)}`)
  const hak = r.placed.filter(p => p.edu === '학사')
  out.push(`G3 미래혁신 학사 1일차=${hak.filter(p => p.team === '미래혁신팀' && p.day === 0).length}`)
  out.push(`G4 학사 종료 전역세션=${Math.max(...hak.map(p => p.day * S + p.slot))}`)
  out.push(`G5 석사 시작 일차=${Math.min(...r.placed.filter(p => p.edu === '석사').map(p => p.day)) + 1}`)
  for (let d = 0; d < r.totalDays; d++) {
    const byRoom: Record<number, Record<string, number>> = {}
    r.placed.filter(p => p.day === d).forEach(p => { const m = byRoom[p.room] ??= {}; const k = p.team + '/' + p.edu; m[k] = (m[k] ?? 0) + 1 })
    out.push(`day${d + 1} seats=${r.placed.filter(p => p.day === d).length}/${S * r.cfg.rooms} ${JSON.stringify(byRoom)}`)
  }
  writeFileSync(resolve(import.meta.dirname, '../../probe.txt'), out.join('\n'))
})
```

`probe.txt` 는 루트에 떨어진다 — 읽고 나서 지운다. vitest 는 `console.log` 를 삼키므로 파일로 쓴다.

### 회귀 테스트 — 핸드오프 §7 안과 다르게 잡은 이유

§7 이 제안한 합성 데이터 `[A 13, B 4, C 4, D 4] · 8세션 4조` 는 **고치기 전에도 통과한다.**
팀 수(4) ≤ 조 수(4) 라 각 팀이 제 조를 하나씩 차지해 세션이 가득 차지 않고, 그래서 A 가
맨 뒤로 밀려도 1일차 상한을 그대로 채운다. 판별력이 없는 테스트다.

**팀 수가 조 수보다 많아야** 재현된다. `[A 6, B 3, C 3, D 3] · 4세션 3조` 로 잡았다 —
고치기 전 A 의 1일차 배치 1명 · 3일, 고친 뒤 4명(상한) · 2일. 고침을 되돌려 **실패하는 것까지
확인**했다.

### 곁가지로 드러난 것 (고쳐 둠)

편성이 바뀌자 두 가지가 드러났다. 둘 다 실브라우저 검증에서만 나왔다.

1. **같은 키의 finding 이 둘 생겨 React key 가 겹쳤다.** 엔진의 ②④ 는 사람 단위로 나오는데
   `src/lite/violations.ts` 의 키는 (날짜·세션·팀) 단위다. 한 팀이 한 세션에 두 명이면 같은 키가
   둘 된다. 키로 접어 하나만 남긴다.
2. **확정한 날짜의 빈자리를 다시 편성이 채우면 재통보에서 빠졌다.** 새로 들어온 사람 본인은
   아직 통보 전이라 괜찮지만 그 팀 면접관은 이미 받은 일정에 면접이 하나 늘어난다.
   `renotifyOf` 에 `added` 종류를 더해 잡는다. 병목 팀 선배치로 1일차에 빈자리가 생기면서
   실제로 재현됐다(나보람 — 1일차 08:00 4조에 새로 배정됨).

`scripts/browser-editor.mjs` 의 드래그 도우미도 고쳤다 — 겨냥한 칸이 실제로 잡혔는지 보지 않아
한 줄 아래 칸에 놓고도 통과하고 있었다(`aim()` 추가).

## 7. 문서 갱신 의무
