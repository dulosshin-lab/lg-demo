# 면접 편성 제약사항 정리 (하드 / 소프트)

편성이 지키는 규칙을 한자리에 모았다. 각 제약마다 **어느 코드가 지키는가 · 끌 수 있는가 ·
어떻게 확인하는가 · 어느 테스트 파일로 재현하는가**를 적었다.

테스트 엑셀은 `data/constraint-tests/` 에 있다 (`node scripts/make-constraint-cases.mjs` 로 다시 만든다).
여기 적힌 수치는 전부 실제로 돌려 잰 값이고, `tests/constraint-cases.test.ts` 가 그 값을 지킨다.

---

## 0. 제약이 사는 자리

```
엑셀 ─▶ ingest ─────▶ resolve ─────▶ sched.js ─────────▶ arrange ────▶ violations.ts
        파서 규칙      대상 선별       편성 엔진            연속 배치 정리   편집 후 재판정
        F1~F4         G1~G3          H1~H4 · S1~S3       S1 · S4        (담당자 수정본)
```

**제약을 어긴 결과를 세는 곳은 둘이다.**

| | 무엇을 보나 | 쓰는 곳 |
|---|---|---|
| `Sched.validate()` | 자동 편성 결과 — 집합 대 집합 | 1차 편성 직후 |
| `src/lite/violations.ts` | 손으로 고친 편성표 — 사람 단위·덩어리 단위 | 편집 화면 |

같은 규칙이지만 세는 단위가 다르다. 편집 화면에서 석사 한 명을 학사 구간으로 옮기면
`validate` 는 "석사 구간 안에 학사 37건이 끼어듦"이라고 손대지 않은 37명을 지목한다.
그래서 편집 판정은 "이 **사람**이 자기 학력 구간 밖에 있나"로 다시 묻는다.

## 1. 하드 제약 — 항상 0건이어야 한다

### H1. 학력을 시간축에서 섞지 않는다 (규칙 ①)

- **내용** — 학사 → 석사 → 박사 순으로 전역 세션 구간을 나눠 쓴다. 한 학력의 구간 안에 다른 학력이 끼면 위반.
- **코드** — `sched.js` 의 `groups` / `slotFrom·slotTo` / `inRange()`, 검증은 `validate().r1`
- **스위치** — `separateEdu`(기본 켬), `eduBoundary`: `'session'`(시간축 연속 블록, 기본) | `'day'`(날짜 통째로 분리)
- **확인** — `validate().r1.length === 0`, 그리고 학력별 전역 세션 구간이 서로 겹치지 않는다
- **케이스** — **C1**
- **주의** — 편집 화면에서는 담당자가 **알고** 옮기는 항목이라 `severity: 'notice'`(조용히 기록)다.
  미팅에서 "학사 사이에 석사가 끼는 것은 안 된다"와 "아니 아니 돼야 돼요"가 함께 나온 자리다.

### H2. 같은 팀은 같은 시간대에 한 명만 (규칙 ②-팀)

- **내용** — 한 팀의 면접위원단은 하나다. 같은 세션에 그 팀 면접이 둘일 수 없다.
- **코드** — `sched.js` 의 `teamBusy`, 검증은 `validate().r2`
- **스위치** — **없다.** 끌 수 없는 규칙이다.
- **파생 결과** — 소요일의 하한이 여기서 나온다:

  ```
  최소 소요일 = ⌈가장 많이 요청한 팀의 건수 ÷ 1일 세션 수⌉      ← Sched.minDays()
  ```

  병목은 면접실이 아니라 면접위원단의 수다. **조를 늘려도 이 값은 내려가지 않는다.**
- **케이스** — **C2** (한 팀 10명 · 하루 8세션 → 반드시 2일)

### H3. 같은 면접관은 같은 시간대에 한 건만 (규칙 ②-면접관)

- **내용** — 팀이 달라도 면접관 이름이 같으면 동시에 두 방에 들어갈 수 없다.
- **코드** — `sched.js` 의 `ivBusy`, 검증은 `validate().r2` (`kind: 'interviewer'`)
- **스위치** — `checkInterviewer`(기본 켬). **끄면 실제로 위반이 발생한다** — 소요일은 줄지만 사람이 겹친다.
- **케이스** — **C3** (두 팀이 면접관 한 명을 공유)

### H4. 자리와 사람의 유일성

- **내용** — ① 한 칸(날짜·세션·조)에 한 명, ② 한 지원자는 한 번만 배치.
  합동면접(여러 팀이 같은 지원자를 요청)이면 요청은 합쳐지고, 그 시간대는 **관련된 팀·면접관 전부**가 점유한 것으로 잡힌다.
- **코드** — `sched.js` 의 `grid`, `resolve()` 의 요청 병합(`reqs`)
- **스위치** — 없다.
- **케이스** — **C4** (요청 11건 → 지원자 8명, 그중 한 명은 3팀 합동)

### H5. 확정 통보분은 움직이지 않는다 (pinned)

- **내용** — 이미 통보한 배정은 재편성해도 그 자리에 고정된다. 정리 패스도 건드리지 않는다.
- **코드** — `sched.js` 의 `cfg.pinned` 선고정, `arrange.ts` 의 `if (who.pinned) continue`
- **스위치** — 없다(통보 여부가 곧 스위치다).
- **확인 방법** — 아무 케이스나 편성 → 일부 날짜를 확정 통보 → 회신을 다시 올리거나 설정을 바꿔 재편성 →
  확정분의 날짜·세션·조가 그대로인지 본다.

## 2. 편성 이전의 하드 필터 — 대상 선별과 파일 서식

편성 엔진에 들어가기 전에 걸러진다. 여기서 빠진 사람은 편성표에 아예 없다.

### G. 대상 선별 (`src/core/resolve/index.ts`) — 케이스 **C8**

| 사유 | 언제 |
|---|---|
| `마스터 미존재` | 회신에는 있는데 취합파일에 없다 |
| `면접관 미매칭` | **어느 팀도** 면접관을 안 적었다 |
| `학력 구분 불명(…)` | `최종학력_학교유형` 이 과정1/2/3 이 아니다 |

일부 팀만 면접관을 안 적었으면 **그 팀 요청만 버리고 지원자는 유지**한다 (`dropped_teams` 에 남는다).

### F. 파일 서식 (`src/core/ingest/`) — 케이스 **C9**

| | 규칙 | 어기면 |
|---|---|---|
| F1 | 헤더 행 = `지원자 번호` 가 있는 **가장 아래** 행 (표준 4행) | 경고만 내고 계속 간다 |
| F2 | 면접관 컬럼 = **헤더 텍스트가 있는 마지막 열** | 헤더명이 달라도 찾아낸다 (`how: 'position'` + 경고) |
| F3 | 그 열의 값이 사람 이름 모양인가 (안전망) | `값 패턴으로 추정` 경고 → 화면에 「사람 확인 필요」 배너 |
| F4 | 표준 컬럼 21개가 다 있는가 | `표준 컬럼 누락: …` 경고 |
| F5 | 마지막 열이 표준/마스터 컬럼이면 면접관 열이 **없는** 파일 | 그 팀 요청 전부 `면접관 미매칭` 으로 제외 |

면접관 헤더명은 실 데이터에서 `면접관`(16) · `팀 면접관`(2) · `면접관 성명`(2) · `인원`(2) 네 가지였다.
`인원` 처럼 '면접관'이라는 글자가 아예 없는 헤더가 있어서 **헤더명으로는 찾을 수 없다** — 위치로 찾고 헤더명은 확인용으로만 쓴다.

## 3. 소프트 제약 — 적을수록 좋다 (0이 아니어도 된다)

### S1. 같은 팀은 연속으로 배치한다 (규칙 ③)

- **왜** — 면접관이 하루에 두 번 나오지 않게. Webex 입·퇴장과 방 예약의 단위다.
  미팅 P0-3: "1일차 전무기술팀처럼 오전 8시 / 오후 1시로 쪼개지면 안 됩니다."
- **코드** — 두 겹이다.
  - `sched.js` `scoreSlot()` — 연속 0 · 같은 조 다른 세션 +30 · 같은 날 다른 조 +45 · 다른 날 +55
  - `src/lite/arrange.ts` — 편성 **결과 위에서** 자리를 맞바꿔 정리한다.
    목적함수 = `3 × 팀 덩어리 + 2 × 면접관 덩어리 + 0 × 빈칸`, 개선될 때만 옮긴다.
- **스위치** — `contiguous`(기본 켬) = arrange 패스
- **확인** — `validate().r3`, `Sched.blocksOf().length`, `ArrangeReport.before/after.teamBlocks`
- **케이스** — **C5**
- **주의** — 순진하게 "쪼개진 팀을 주 덩어리에 붙이기"만 하면 조가 분산돼 오히려 나빠진다(실측 ③ 6→13).
  조 = 물리적 면접방이라 방을 옮기는 순간 면접관이 옮겨 다녀야 한다.

### S2. 첫 타임을 피한다 (규칙 ④)

- **내용** — 오전·오후 **첫 세션**은 수요가 가장 적은 팀에게 준다. 다른 팀이 들어가면 위반으로 센다.
- **코드** — `sched.js` `scoreSlot()` 의 `+22` 가점, `validate().r4`
- **스위치** — `avoidFirstSlot`
  - `'off'` — 안 본다
  - `'soft'`(기본) — 비용에 가점만 준다. 자리가 없으면 들어간다
  - `'hard'` — **첫 타임을 비워서라도** 안 넣는다. 공석을 허용한다
- **케이스** — **C6**
- **주의 (계측으로 확인)** — `'hard'` 로 두어도 **정리 패스(S1)가 첫 타임으로 다시 끌어온다.**
  `arrange` 가 보존하는 것은 ①②뿐이다. `hard` + `contiguous` 조합에서 ④ 위반 0 → 2 로 되돌아온다.
  또 `hard` 는 자리가 모자라면 **미배정**을 만든다(C6에서 1명).

### S3. 병목 팀을 먼저 앉힌다 (규칙 ⑤, 2026-09-02 추가)

- **내용** — 학력 그룹 안에서 **하루 세션 수를 넘는 팀을 먼저** 배치한다. 그다음은 종전대로 수요 오름차순(④).
- **왜** — ④만 따라 수요 오름차순으로 넣으면 작은 팀들이 첫날을 채우는 사이 병목 팀이 맨 뒤로 밀린다.
  그 팀이 넘긴 인원이 다음 날로 가는데 ②(한 팀은 한 세션에 한 명) 탓에 **남은 팀 수만큼만 열이 차서 격자가 반쪽으로 빈다.**
  실측(60명·8세션·4조): 2일차 15/32석, 1조 열이 통째로 공석 → 26/32석으로 개선.
- **코드** — `sched.js` 의 `bottleneck()` + `order` 정렬
- **스위치** — 없다(항상 적용).
- **케이스** — **C7** (한 팀이 12명 = 하루 상한 8 초과)

### S4. 면접관이 하루에 한 번만 들어온다

- **내용** — S1의 팀 덩어리와 별개로, **면접관 개인**의 하루 등장 덩어리를 센다.
  한 사람이 여러 팀을 겸하면 팀이 붙어 있어도 그 사람은 두 번 나와야 할 수 있다.
- **코드** — `arrange.ts` `metricsOf()` 의 `ivBlocks` / `ivSplit`, 목적함수 가중치 2
- **케이스** — **C5** (`ivSplit` 4 → 2)

### S5. 빈칸(holes) — **일부러 끄고 있다**

- 목적함수의 `hole` 가중치는 **0**이다. 켜면 빈칸 20→16을 얻는 대신 팀 덩어리가 24→25로 늘었다(실측).
  연속 배치와 반대 방향으로 당긴다.
- 빈칸을 실제로 좌우하는 것은 **조 수**다 — 조를 하나 줄이면 빈칸 20→12로 떨어지고 일수는 그대로였다.
  효과가 작은 손잡이를 담당자에게 쥐여 주는 것보다 조 수를 보게 하는 편이 낫다.

## 4. 설정 스위치 ↔ 제약

`src/lite/setup.ts` 의 `Setup` → `toCfg()` → `sched.js`

| 설정 | 기본값 | 걸리는 제약 |
|---|---|---|
| `separateEdu` | `true` | H1 — 끄면 학력이 섞인다 |
| `eduBoundary` | `'session'` | H1 — `'day'` 면 학력마다 날을 따로 쓴다(일수 증가) |
| `checkInterviewer` | `true` | H3 — 끄면 면접관이 겹친다 |
| `avoidFirstSlot` | `'soft'` | S2 |

| `sessions` | 8 | H2의 하루 상한 |

| `skipWeekend` · `holidays` | 켬 · 없음 | 날짜 계산만 (편성 자체는 날짜 인덱스만 쓴다) |

## 6. 쓰는 법

1. `npm run dev` → 화면에서 **취합파일.xlsx 먼저**, 그다음 `희망지원자_*.xlsx` 전부를 올린다.
   케이스 폴더 하나가 한 세트다. **폴더를 섞지 않는다** (지원자번호 대역은 안 겹치게 만들었지만 팀 이름이 겹친다).
2. 설정 화면에서 그 케이스가 겨누는 스위치를 켰다 껐다 하며 편성표와 위반 배너를 비교한다.
3. 코드로 한 번에 확인하려면:

   ```bash
   npx vitest run tests/constraint-cases.test.ts     # 13건
   node scripts/make-constraint-cases.mjs            # 엑셀 다시 만들기
   ```

## 7. 알아 둘 것

- **소요일은 조 수로 못 줄인다.** H2가 하한을 정한다(`minDays`). 조를 늘리면 빈칸만 는다.
- **정리 패스(S1)는 ①②만 보존한다.** ④는 되돌려 놓을 수 있다(C6). 확정분(H5)은 건드리지 않는다.
- **`avoidFirstSlot: 'hard'` 는 미배정을 만들 수 있다.** 첫 타임을 비우느라 자리가 모자란다.
- **③의 건수는 세는 곳마다 다르다.** `validate` 는 '조 분산'과 '세션 끊김'을 따로 세고,
  편집 판정(`violations.ts`)은 담당자가 신경 쓰는 **덩어리 수**로 센다. 숫자를 비교할 때 기준을 맞춰야 한다.
- **`sched.js` 는 함부로 고치지 않는다.** 실측 검증을 마친 코드다. 고치면 여기 적힌 수치를 전부 다시 받아야 한다.
